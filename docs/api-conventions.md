# API 컨벤션 가이드

## 1. Swagger 태그 규칙

### 태그명 패턴

| 구분 | 패턴 | 예시 |
|------|------|------|
| 클라이언트 API | `"도메인명"` | `"모임"`, `"신청"`, `"리뷰"` |
| 관리자 API | `"도메인명 (관리자)"` | `"모임 (관리자)"`, `"신청 (관리자)"` |
| 홈 화면 복합 | `"홈 화면 (도메인명)"` | `"홈 화면 (모임)"`, `"홈 화면 (리뷰)"` |

> 혼용 금지: `"관리자 - X"`, `"X 관리 (관리자)"` 패턴은 사용하지 않는다.

### Swagger UI 노출 순서

클라이언트 API → 관리자 API 순서. SwaggerConfig에 `.addTagsItem()` 으로 고정.

**클라이언트 (1~11)**
1. 인증
2. 회원
3. 모임
4. 신청
5. 장소
6. 리뷰
7. 마일리지
8. 홈 화면 (모임)
9. 홈 화면 (리뷰)
10. 캐러셀
11. 이미지

**관리자 (12~18)**
12. 회원 (관리자)
13. 모임 (관리자)
14. 신청 (관리자)
15. 장소 (관리자)
16. 리뷰 (관리자)
17. 마일리지 (관리자)
18. 캐러셀 (관리자)

## 2. @Operation 규칙

- `summary`: 기능을 짧게 (예: "모임 목록 조회")
- `description`: 인증 요건, 파라미터 특이사항, 예외 동작 등 보조 설명. 자명한 경우 생략 가능.

---

## 3. API 경로 규칙

| 규칙 | 예시 |
|------|------|
| 복수형 명사 자원 | `/api/gatherings`, `/api/users` |
| 계층 자원 | `/api/gatherings/{id}/applications` |
| 상태/액션 변경 | `PATCH /api/gatherings/{id}/status` |
| 인증 흐름 (예외적 동사 허용) | `POST /api/auth/login`, `/api/auth/logout` |
| 관리자 전용 | `/api/admin/{domain}/...` |

---

## 4. 도메인 경계 — auth vs user

| 기능 | 도메인 | 근거 |
|------|--------|------|
| 회원가입 | auth | 토큰 발급 흐름 포함 |
| 로그인 / 로그아웃 / 토큰 갱신 | auth | 세션·토큰 관리 |
| 비밀번호 찾기 (비로그인) | auth | 비로그인 상태 인증 절차 |
| 비밀번호 변경 (로그인 상태) | user | 계정 정보 수정 |
| 프로필 조회 / 수정 | user | 계정·프로필 관리 |
| 이메일·닉네임 중복 확인 | user | 회원 정보 검증 |
| 회원 탈퇴 | user | 계정 비활성화 |

---

## 5. admin/client 폴더 분리 기준

관리자 전용 기능(CRUD, 상태 변경 등)이 존재하는 도메인은 `admin/`, `client/`, `common/` 으로 분리.
